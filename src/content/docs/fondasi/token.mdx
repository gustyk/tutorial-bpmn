Token adalah model mental untuk mengikuti kemajuan alur. Anggap token sebagai penanda yang bergerak melalui flow node. Token bukan objek fisik dan detail eksekusi engine dapat menambah perilaku teknis.

Diagram di atas memperlihatkan dua cabang paralel yang bertemu kembali. Gunakan tombol **Putar** untuk melihat seluruh perjalanan token atau maju per tahap. **Parallel Gateway** pada model BPMN yang sebenarnya memiliki simbol dan semantik formal; simulasi ini hanya memperlihatkan perilaku token.

1. Start membuat satu token dan mengaktifkan alur proses.
2. Token menjalankan Task A.
3. AND split meneruskan kontrol ke kedua jalur; terbentuk token pada masing-masing cabang.
4. Task B dan Task C berjalan paralel dan dapat selesai pada waktu berbeda.
5. Jika satu token tiba lebih dulu, AND join menunggu token dari cabang aktif lainnya.
6. Setelah kedua token tiba, AND join melepas satu token untuk melanjutkan alur ke End.

> **[PEDAGOGICAL SIMPLIFICATION]** Token membantu kita menalar alur kontrol. Ia bukan kartu yang secara literal dikirim oleh engine; aturan eksekusi BPMN memiliki detail formal.

## Empat perilaku yang wajib dibedakan

- **Branching:** satu token membuat beberapa jalur aktif (AND) atau memilih satu/lebih jalur (XOR/OR sesuai kondisi).
- **Waiting:** catch event menahan kemajuan sampai pemicu datang.
- **Synchronization:** gateway join menunggu sesuai jenis gateway dan cabang yang aktif.
- **Interruption:** boundary event interrupting menghentikan activity yang dipasangi; non-interrupting membuka jalur tambahan sementara activity terus berjalan.

## Diagnostik

Jika satu cabang selesai, apakah proses boleh lanjut atau harus menunggu cabang lain? Jika kedua cabang masuk ke XOR merge tanpa AND join, masing-masing token dapat meneruskan alur dan menjalankan task hilir lebih dari sekali.

**Ingat:** simulasikan setiap token sampai end atau exception; jangan menyimpulkan perilaku hanya dari bentuk gambar.
