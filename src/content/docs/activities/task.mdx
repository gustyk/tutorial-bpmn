## Memilih task type

| Notasi | Makna ringkas | Contoh |
|---|---|---|
| None / Undefined | Pekerjaan tanpa task type khusus | Tinjau Permohonan |
| User Task | Manusia menyelesaikan pekerjaan dengan bantuan workflow/task UI | Validasi Klaim |
| Manual Task | Manusia melakukan pekerjaan tanpa engine mengorkestrasi detailnya | Periksa Dokumen Fisik |
| Service Task | Pekerjaan oleh layanan/worker | Hitung Ongkir |
| Script Task | Eksekusi script yang dikonfigurasi | Normalisasi Kode |
| Business Rule Task | Evaluasi aturan/keputusan bisnis | Tentukan Kategori Risiko |
| Send Task | Mengirim pesan sebagai pekerjaan | Kirim Konfirmasi |
| Receive Task | Menunggu/menerima pesan sebagai pekerjaan | Tunggu Respons Bank |

Nama task type BPMN tidak otomatis menentukan bagaimana implementasi dibuat. Contoh: User Task tidak berarti aktor harus berada dalam lane bernama “User”.

## Markers

- **Loop:** satu aktivitas diulang selama kondisi loop berlaku; iterasi satu per satu.
- **Multi-instance sequential:** banyak instance dikerjakan berurutan.
- **Multi-instance parallel:** banyak instance dibuat sebagai kumpulan; tidak menjamin mesin CPU mengeksekusinya serentak.
- **Compensation marker:** task didefinisikan sebagai handler kompensasi, bukan task biasa yang muncul lewat Sequence Flow.

## Salah paham yang sering terjadi

- **“User Task dan Manual Task sama.”** User Task disajikan untuk dikerjakan manusia melalui mekanisme workflow; Manual Task menggambarkan kerja manual yang tidak dikendalikan engine sebagai task UI.
- **“Service Task berarti harus memakai satu API tertentu.”** Notasi menunjukkan jenis pekerjaan, bukan protokol implementasinya.
- **“Parallel multi-instance berarti parallel secara fisik.”** Semantik mengizinkan instance independen; kapasitas runtime tetap menentukan concurrency aktual.

## Argumen

“Kami menggunakan User Task karena pemeriksaan membutuhkan keputusan petugas dalam aplikasi dan hasilnya menyelesaikan work item. Manual Task ditolak karena model ini perlu merepresentasikan assignment dan penyelesaian melalui workflow.”
